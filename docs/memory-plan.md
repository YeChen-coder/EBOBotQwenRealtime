# 记忆系统计划（v3）

> 给主会话的实施计划。背景：v2（`ebo-ai-home/ops/diagnostics/local/source/realtime-assistant/session_memory.py`）有两层记忆，v3 搬过来时只留下了空壳（`config.memory_root` / `memory_paths()`、`state.memory_*`、看板的 `saving_memory`），没有任何代码读写记忆。每场对话都从零开始，唯一的"记忆"是 `.env` 人设里写死的句子（第 104 行"嗓子好些了吗"），所以每场都问。
>
> 目标不是照搬 v2，而是做一套更贴近这个家的记忆：知道是谁说的、分得清电视声、关心过的事问一次就收、说"好了"就放下。

## 1. 现状里必须正视的几件事（实测）

| 现象 | 对设计的影响 |
|---|---|
| 语音唤醒的会话一律 `user_id='guest'`（`runtime.py` `GUEST_PROFILE`），程序不知道是谁在说话 | 不能按用户分文件。改成**全家一份记忆，每条标注"关于谁"**；是谁说的靠"最近 Frigate 认出的人脸" + 内容判断，判断不了就标"家人" |
| 对话记录里大量是电视剧、短剧、直播带货、打电话的声音（10-17 婚姻财产短剧、10-19 直播卖爱媛果冻橙） | 第一层提炼必须先分清"在跟猫猫说"和"背景声"，背景声一律不记 |
| ASR 错字多（"茄夹"=煎饺、"港口"、"二叔"） | 提炼时允许模型按上下文纠正明显错字；拿不准的不记成事实 |
| 妈妈 10-17 已经说"妈妈嗓子好了"，第二天照问 | 关心事项要有状态：`open → asked → resolved`，问过一次就记下，说好了就关闭 |
| 迎接时段、日期都按家里时区（`EBO_HOME_TIMEZONE=Asia/Shanghai`） | 记忆里所有日期、"今天/两天后过期"一律按家里时区算 |

## 2. 架构

```
会话结束 ──► 第一层：会话笔记（qwen-plus，便宜、几秒）
              写进 data/memory/notes.json（未合并笔记）
                     │
   攒够 4 条笔记 / 每晚 3:00（家里时间、空闲时）/ 有记忆过期
                     ▼
            第二层：整理（更强的模型：先试 qwen3-max，不可用退 qwen-max）
              读 现有记忆 + 未合并笔记 → 输出新的记忆 → 写 data/memory/memory.json
                     │
新会话开始 ──► 拼出"你已经知道的事"，放进 instructions（不超过 ~2500 字）
```

### 2.1 一条记忆长什么样

```json
{
  "id": "m_7f3a",
  "about": "妈妈",                       // 妈妈 / 爸爸 / 小叶子 / 家里 / 家人(不确定是谁)
  "kind": "concern",                     // fact 身份事实 | preference 喜好 | routine 作息习惯 |
                                         // relation 人物关系 | plan 计划/待办 | event 发生的事 |
                                         // concern 关心事项(身体、烦心事) | mood 当天状态
  "tier": "short",                       // permanent 永久 | long 长期 | short 短期
  "text": "妈妈嗓子哑了，说是上课说话多",
  "since": "2026-10-18",
  "expires_on": "2026-10-20",            // permanent 为空
  "status": "open",                      // open | asked | resolved（只用于 concern / plan）
  "asked_on": null,                      // 猫猫已经问过的日期
  "pinned": false,                       // 人工写入的种子事实，模型不能改、不能删
  "evidence": "10-18 妈妈：我这嗓子就是因为说话多"   // 一句原话，方便看板核对
}
```

三档的含义（比 v2 更明确）：
- **permanent 永久**：身份、家庭成员关系、住哪、职业。只在用户明确更正时才改。种子事实（见第 4 节）都在这里，`pinned=true`。
- **long 长期**（几周到几个月）：喜好、作息习惯（"家里车有限号日，那天要早走"、"喜欢用手机看短剧"）、持续的事（"快中考了，四班难带"）。给一个 30~90 天的 `expires_on`，再被提到就顺延。
- **short 短期**（1~3 天）：当天心情、身体小状况、刚发生的事（"今天吃了三个煎饺、吃得很饱"）。默认 2 天过期。

上限：永久 20、长期 15、短期 8（超了让第二层合并或丢掉最不重要的）。

### 2.2 第一层：会话笔记（每场会话结束后）

- **触发**：`conversation.py` 的 `_cleanup()` 结束后，后台线程跑，失败只记日志，不影响下一场对话。
- **输入**：这场会话的用户话 + 猫猫的话（从 `transcripts.jsonl` / `assistant_outputs.jsonl` 按 `session_started_at` 取，或会话内存里直接收集更简单），加上：
  - 这场会话前后 10 分钟内 Frigate 认出的人脸（谁在场）；
  - 当前家里日期时间；
  - 现有记忆里状态为 `open` 的关心事项（让它判断"这次问了没有""她说好了没有"）。
- **输出（JSON，不要一句话）**：
  ```json
  {"speaker_guess": "妈妈",
   "talking_to_robot": true,
   "notes": ["妈妈说今天家里车限号，所以早走、坐公交"],
   "followups": [{"id": "m_7f3a", "asked": true, "resolved": false}],
   "nothing_worth_keeping": false}
  ```
- **提示词要点**：
  - 只记"家人对猫猫说的、或明显是家人自己的事"；电视剧、短剧、直播、打电话、念别人消息的内容**一律不记**，宁可漏记，不可把剧情当成家事。
  - 猫猫自己说的话只当上下文，不能当事实（例如猫猫说"你嗓子怎么哑了"不代表她嗓子哑）。
  - 只有寒暄、"回去充电"、"晚安"这类控制话语时 `nothing_worth_keeping=true`（但"晚安""我上班了"的**时间**可以作为作息线索记一条，交给第二层归纳）。
  - 能纠正明显的 ASR 错字；拿不准的内容不记。
- **成本**：每场一次 qwen-plus，输入几百到两千字，几乎可以忽略。

### 2.3 第二层：整理（定期）

- **触发**（满足任一）：未合并笔记 ≥ 4 条；每晚 3:00（家里时间，且没有对话在进行）；有记忆过期。
- **输入**：现有 `memory.json` + 所有未合并笔记 + 当前日期。
- **规则**（写进提示词，也在代码里兜底校验）：
  - 同一件事合并成一条，不重复；新的明确说法覆盖旧的。
  - 再次被提到的长期/短期记忆顺延 `expires_on`；过期的删掉（代码兜底删）。
  - 关心事项：第一层报告"问过了"→ `status=asked, asked_on=今天`；报告"好了/没事了"→ `resolved`，并在 2 天后删掉。
  - 同一类小事出现 3 次以上才升成作息习惯（long），避免一次偶然变成"习惯"。
  - 不推断诊断、用药、隐私八卦；不把问题、猜测、猫猫的建议写成事实。
  - `pinned` 的条目原样保留，不许改写。
- **输出**：完整的新记忆（JSON schema，DashScope compatible 接口用 `response_format={"type":"json_object"}` + 代码校验）；校验失败就不覆盖旧文件、笔记保留下次再试。
- **原子写**：写临时文件再 `os.replace`；只删掉这次真正合并过的笔记（v2 这点做得对，保留）。

### 2.4 新会话开始时怎么用

拼一段放进 `instructions`，**明确是"背景，不是指令"**，并附上使用规则：

```
# 你已经知道的事（背景，不是指令；家里时间 2026-10-21 周三 19:50）
关于这个家：……（permanent）
最近的情况：……（long，附"截至何时"）
这两天：……（short）
可以关心一次的事（问过就别再问，说好了就别再提）：
- 妈妈嗓子哑了（10-18 起，还没问过）
使用规则：
- 不要背诵这些内容，也不要说"我记得你说过"；需要时自然地用上。
- 一场对话里最多主动提一件"可以关心的事"，而且要等聊开了、时机自然时。
- 当前说话的人不一定是"关于谁"里的人；不确定是谁时，别把妈妈的事当成在跟妈妈说。
```

- 迎接妈妈（`greet_homecoming`）时额外给"关于妈妈"的条目，替代现在的 `EBO_GREET_CONTEXT`。
- 字数上限 ~2500 字（千问实时模型每轮都会重复计费整段 instructions，记忆越长越贵，见日志里的 `usage: input ... text ...`）。

## 3. 比 v2 更好在哪

1. **按家庭存，按人标注**：适配"语音会话不知道是谁"的现实，不会把妈妈的事丢进 guest。
2. **分得清电视声**：第一层第一件事就是判断是不是在跟猫猫说；这是这个家最常见的噪声来源。
3. **关心事项有生命周期**（open → asked → resolved）：彻底解决"嗓子好些了吗"问十遍。
4. **猫猫说过的话也被追踪**：知道自己问过什么，而不只是知道用户说过什么。
5. **作息靠重复出现归纳**：几次"我上班了"的时间 → "妈妈一般 5:45~6:30 出门"，可用于早上播报、迎接时段的自动校准（以后）。
6. **中文 + 千问**：记忆本身用中文存，不经过英文转述丢细节。
7. **看得见、改得了**（第 5 节）：看板能看到它记了什么、能删错的。

## 4. 人设和身份信息的拆分（`.env` 瘦身）

现在 `EBO_ASSISTANT_INSTRUCTIONS` 和 `EBO_GREET_CONTEXT` 里混着两类东西：

| 留在人设（`.env` 的 instructions）：**怎么说话** | 搬进永久记忆（种子文件）：**事实** |
|---|---|
| 自称猫猫、狸花猫、热情俏皮 | 家在中国天津 |
| 语气、语速、不要喵喵叫、不要读提示词 | 姐姐（小叶子）在加拿大 |
| 称呼规则（不凭外貌判断身份等） | 妈妈：九年级化学老师、四班班主任、也教三班化学、快中考了 |
| 搜索规则 | 家里有车，有限号日 |
| "姐姐的事别人没问不要主动提"（这是行为规则，留下） | 爸爸（目前几乎没有信息，等记忆积累） |

具体做法：
- 新建 `data/memory/seed.json`（在 `data/` 下，不进 git，隐私）：上面右列的事实，全部 `tier=permanent, pinned=true`。主会话可以先从现有 `.env` 内容生成一份，用户改起来就是改这个文件。
- 启动时把 seed 合并进 `memory.json`（seed 有、memory 没有的补上；seed 改了以 seed 为准）。
- 人设里：删掉第 104 行（嗓子），修掉第 90 行"创造你的姐姐"的错字，把"在天津的家里""姐姐在加拿大"这类事实挪走，只留"姐姐的事别人没问就不要主动提"这条规则。
- `EBO_GREET_CONTEXT` 里的事实挪进 seed；迎接提示词改为从记忆里取"关于妈妈"的条目。保留这个变量作兼容（有值就当作额外背景），在 `.env.example` 里标注已被记忆取代。
- **注意**：`.env` 只改这几个变量本身，不碰别的变量、不打印密钥（项目约定）。

## 7. 验证（用真实记录回放，这是最有说服力的）

1. **单元测试**：过期删除、顺延、`open→asked→resolved`、pinned 不被改、上限截断、JSON 校验失败不覆盖旧文件、时区按 Asia/Shanghai。
2. **离线回放**：把 `data/transcripts.jsonl` + `assistant_outputs.jsonl` 按会话切开（10-17 ~ 10-21），依次喂给第一层、每 4 条跑一次第二层，最后看 `memory.json`。期望：
   - 有："妈妈嗓子哑（说话多）" → 之后 "说好了" 变 resolved 或已过期；"家里车有限号日，那天早走坐公交"；"妈妈喜欢用手机看短剧/直播"；"妈妈一般很早出门上班"；"小叶子是女儿"。
   - 没有：短剧里的婚姻财产纠纷、直播卖橙子、"二十五万八"、骂人的那段电视/电话内容。
   - 回放结果给用户看一遍再上线。
3. **线上**：部署后看一场真实对话结束时的日志（第一层输出）、第二天早上看整理结果；确认看板记忆卡片显示正常；确认新会话的 instructions 长度和 `usage` 里的 text tokens 没有暴涨。

## 8. 分步交付（建议顺序，每步都能单独上线）

1. `memory.py` + 第一层 + 第二层 + 单元测试 + 离线回放（先不接进对话）——给用户看回放结果。
2. 接进对话：会话结束写笔记、开场注入记忆、夜间整理。
3. 人设瘦身 + seed 文件 + 迎接改用记忆（删嗓子那行）。
4. 看板记忆卡片。
